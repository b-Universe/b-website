Navigating Our Domain

The behr.dev network utilizes multiple subdomains to organize various hosted services, tools, and projects.

The following is a technical breakdown of the active endpoints currently routed through the network and their respective functions.

home.behr.dev

The central hub of the network. It serves as the primary portfolio, development blog repository, and service listing page.

This entire frontend is built from scratch using plain HTML, CSS, and JS, served securely as a static site.

Visit Home

play.behr.dev

The front door to B. This endpoint serves the live WebGL game client.

By routing the game through its own subdomain, players can connect directly to the top-down, multiplayer voxel world straight from their browser without needing to navigate through the portfolio or download any external clients.

Launch B

wiki.behr.dev

The dedicated documentation and lore repository for B.

Provides detailed information on specific mechanics, custom DenizenScript server interactions, and the history and lore of the world.

Read the Wiki

jelly.behr.dev

A self-hosted media streaming server powered by Jellyfin.

Running this on a subdomain allows authorized users to securely organize and stream media collections without relying on third-party subscriptions or restrictive external platforms.

Access Media

tiny.behr.dev

A custom static URL router and link shortener.

Instead of relying on external services, long or complex URLs are routed through this subdomain to keep community and project links clean and managed under the behr.dev umbrella.

View on GitHub

discord.behr.dev

A simple but effective routing alias.

Instead of utilizing standard Discord invite strings that may expire or change, this subdomain acts as a permanent, clean redirect straight into the B community Discord server.

Join Discord

desk.behr.dev

A self-hosted RustDesk relay and signal server running on a Raspberry Pi.

Provides secure, private remote desktop access and support functionality across devices without relying on external third-party infrastructure.

About RustDesk

Behind the Scenes: Routing

To make all of this work seamlessly, the infrastructure relies on a Reverse Proxy (typically Nginx or similar) sitting at the edge of the network.

DNS records point to the main server IP, where the reverse proxy intercepts incoming requests. It reads the subdomain and routes the traffic to the appropriate internal service or port. For example, play.behr.dev routes to the Node.js game server, while home.behr.dev routes to the static file server.

This architecture allows a single machine to host multiple distinct applications simultaneously and securely, providing human-readable URLs for each service.
