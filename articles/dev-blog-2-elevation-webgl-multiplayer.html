Dev Blog #2:
Elevation, WebGL, and Multiplayer

Early Combat Implementation

When we first started building the game, combat was very basic. We only had simple melee attacks working across a flat map.

It served its purpose for testing hit detection and core mechanics, but the limited directions made fighting feel a bit stiff. We knew we had to completely overhaul the system to make it feel fluid and natural.

$3 well spent!

Building Hills and Tinting Blocks

Before we moved over to the big WebGL engine, I spent time figuring out how to actually generate world elevation. I wanted real hills and cliffs.

Along with the hills, we added tintable blocks. This is how we got the water to actually look like water. Instead of drawing a million different colored blocks, we can just take a base block and tint it whatever color we need.

Climbing and Collision

Drawing a 3D hill on the screen is one thing, but making the player walk on it correctly is a lot harder. We had to do a lot of math to get the collisions working right.

If the collision is wrong, you just fall straight through the floor or get stuck inside a wall. After a lot of testing, the player can finally run up and down the elevation smoothly without breaking the game.

The Big WebGL Upgrade

As we added more hills and more blocks, the game started to have network issues. The old way of drawing the map just couldn't handle it. We decided to do a massive upgrade and move the whole engine over to WebGL using Three.js.

We built a custom InstancedMesh pipeline. This is a fancy way of saying we tell the graphics card to draw the exact same block shape thousands of times in one go. Instead of lagging, the game can now render massive worlds smoothly.

Future-Proofing the Map

To make the WebGL upgrade work, we completely changed how the game loads images. Loading a hundred separate block files is bad for performance. Instead, we packed all our block textures into one giant image called a texture atlas.

We also set up a numeric registry system. The game just reads simple ID numbers for blocks now. This makes the game run way faster and future-proofs the engine so we can add tons of new materials later without breaking anything.

Multiplayer and Chat Bubbles

A game is way more fun with friends. We hooked up Node.js and Socket.io to get real-time multiplayer working. Seeing someone else run around the map you built is a great feeling.

We added a chat system with bubbles that pop up right over the characters. While Icecapade and I were testing it out, he helped me decide on adding support for extra chat bubbles and folding text!

Building and Bloopers

To make building a lot faster we made a new multi-block selection tool. Trying to test it out on the new hills led to some pretty funny results.

While these test hills were manually placed, getting the climbing mechanics working here has us incredibly excited to tackle proper procedural terrain generation with natural elevation soon!

8-Direction Attacks

Remember the teaser from the last blog? We didn't stop at just running around. We also got a stack of attack animations working smooth in all 8 directions!
